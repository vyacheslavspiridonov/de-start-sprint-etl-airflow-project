## Отправка запросов к S3 через curl

### Основные элементы 

**API-интеграция** осуществляется через два основных endpoint:
* POST-запрос для генерации отчета
* GET-запросы для получения данных

### Ключевые параметры запросов

**Обязательные заголовки** для работы с API:
* X-Nickname
* X-Cohort
* X-Project
* X-API-KEY

### Структура данных

**Основной отчет** содержит:
* Уникальный task_id
* Статус выполнения (SUCCESS)
* Данные отчета с:
  * report_id
  * Период (start_day и end_date)
  * Ссылки на файлы в S3

### Типы доступных данных

**Базовые файлы** включают:
* customer_research.csv
* user_order_log.csv
* user_activity_log.csv
* price_log.csv

**Инкрементальные данные** содержат аналогичные файлы с суффиксом _inc:
* customer_research_inc.csv
* user_order_log_inc.csv
* user_activity_log_inc.csv
* price_log_inc.csv

### Важные особенности

* Все данные хранятся в **S3-хранилище**
* Доступ к данным осуществляется через уникальные идентификаторы
* Система поддерживает как полные отчеты, так и инкрементальные обновления
* Для получения инкрементальных данных требуется указывать конкретную дату

## Скрипт по обновлению таблиц Staging-слоя с созданием пользовательского типа данных

### Основные моменты скрипта

**Главная цель скрипта** — добавление нового столбца со статусом заказа в две таблицы.

**Ключевые элементы:**
* Создается новый тип данных `status` в схеме `staging`
* Тип данных представляет собой перечисление (ENUM) с двумя возможными значениями:
  * `shipped` (отправлен)
  * `refunded` (возврат)

**Модификации таблиц:**
* В таблицу `staging.user_order_log` добавляется новый столбец `status`
* В таблицу `mart.f_sales` также добавляется столбец `status`
* Оба столбца используют созданный тип данных `staging.status`

**Важное примечание:** данный скрипт позволяет отслеживать только два статуса заказа, что может быть недостаточно для полноценной системы отслеживания заказов.

## Создание витрины данных

### Основная цель скрипта
Анализ **клиентского удержания** с детализацией по товарам и временным периодам.

### Ключевые элементы анализа

**Временная гранулярность:**
* Анализ ведется по неделям
* Каждый период имеет уникальный идентификатор

**Классификация клиентов:**
* **Новые клиенты** (первая покупка)
* **Вернувшиеся клиенты** (были предыдущие покупки)

### Основные метрики

**Финансовые показатели:**
* Доход от новых клиентов
* Доход от вернувшихся клиентов

**Клиентские метрики:**
* Количество новых клиентов
* Количество вернувшихся клиентов
* Количество клиентов с возвратами
* Общее количество возвратов

### Особенности обработки данных

**Работа с возвратами:**
* Возвраты учитываются со знаком минус в сумме заказа
* Создается специальная метка для возвратов

**Определение новизны клиента:**
* Клиент считается новым, если текущая дата заказа совпадает с первой датой его заказа
* Учитывается исключение для случаев, когда возврат происходит без предыдущей покупки в данных

### Результат анализа

Отчет формируется в разрезе:
* Временного периода
* Категории товара
* Статусов клиентов

Все показатели агрегируются по указанным разрезам с возможностью сортировки по периоду и товару.

## Объединение задач в направленный граф AirFlow

### Основные компоненты DAG

**Главная цель DAG:** автоматизация загрузки и обработки данных о продажах.

### Ключевые этапы обработки

1. **Генерация отчета:**
* Отправка POST-запроса для запуска генерации данных
* Получение task_id для отслеживания статуса

2. **Получение данных:**
* Ожидание завершения генерации отчета
* Получение report_id после успешного выполнения
* Загрузка инкрементальных данных

3. **Загрузка в базу:**
* Скачивание CSV-файлов с S3
* Предварительная обработка данных
* Загрузка в staging-слой PostgreSQL

### Структура данных

**Основные таблицы:**
* **Staging-слой:** user_order_log
* **Mart-слой:**
  * d_item (справочник товаров)
  * d_customer (справочник клиентов)
  * d_city (справочник городов)
  * f_sales (факты продаж)

### Параметры выполнения

**Расписание:**
* Запуск ежедневно
* Период работы: с 5 августа 2026 по 31 декабря 2026

**Важные особенности:**
* Обработка инкрементальных данных
* Предварительная очистка данных (удаление дубликатов)
* Добавление статуса заказа по умолчанию ('shipped')
* Загрузка через PostgreSQL

### Последовательность выполнения

1. Генерация отчета
2. Получение ID отчета
3. Загрузка инкремента
4. Обработка и загрузка данных
5. Обновление справочников
6. Формирование фактов продаж
